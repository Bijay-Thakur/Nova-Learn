# Authentic Assessment Engine (Engine 2)

This is an additive edit to the existing professor workspace. Course Compiler remains Engine 1. Existing checkpoints, demonstrations, learning records, and mastery logic are retained. No new database migration or dependency is required; the existing three SQL files remain necessary.

## Professor workflow

Open Assessment Studio → Design engine. Choose an approved module and up to eight objectives (Final project can span the course), assessment category/format, emphasis, time budget, difficulty, verification depth, collaboration, permitted resources and AI policy. Recall-only questions are capped at five and at 25% of task minutes. Diagnostics/pulse checks remain in Module Studio, unchanged.

Create a saved design, then run each of six bounded stages:

1. **Objective → evidence:** observable performance, artifact, reasoning and transfer specifications per objective.
2. **Strategy:** the evidence sequence and accessible alternatives.
3. **Scenario & tasks:** a hypothetical applied case, instructions, objective-linked tasks, source IDs and minute estimates.
4. **Rubric & levels:** exactly one weighted criterion per objective, totaling 100%, with excellent/proficient/developing/beginning descriptors.
5. **Variants & verification:** equivalent-context variants, two adaptive follow-up strategy, transfer task and a professor-private evaluation guide.
6. **Calibrate & validate:** deterministic coverage/reference/workload checks plus a model alignment audit. Blocking findings prevent approval.

Each stage is schema-validated and persisted independently with optimistic version checks. Stage 1–2 use the existing `NOVA_DRAFT_*` route; 3–6 use `NOVA_JUDGE_*`. Successful completion requires six generation calls, not an autonomous agent swarm. Existing gateway timeouts, token caps, per-user request budget and configurable OpenAI/Gemini/Groq/local-compatible providers apply. Configured `judge` is a route, not a guarantee of stronger model quality; select appropriate models in your server environment.

Stages reuse up to five relevant approved source chunks. No external research, hidden crawling, or automatic source approval occurs. A source-free result is labeled ungrounded. Hypothetical scenario parameters are distinct from cited course facts. Source IDs are validated; factual accuracy still requires professor review.

Edit outputs and save. Changing a stage clears dependent outputs and approval, not preceding work or other assessments. Changing settings or relevant source/objective context resets this design. “Regenerate from here” resets that stage and downstream stages. Failed model output never replaces successful content. Live failures persist a retryable log. Closing the page stops orchestration; there is no background queue.

## Approval and publication

Only a professor may create, generate or approve. Approval is a dedicated authenticated action, not a client-provided approval flag. It requires complete validated output and no blocking findings. An approved package becomes a normal checkpoint, with its public authentic-assessment metadata. Release remains a separate action and honors Course Compiler final review and chapter-release controls. Existing publication remains unchanged until release succeeds.

Student publication removes the entire private `assessmentDesigns` collection. Public package includes the brief, tasks, objectives, evidence expectations, rubric levels, time, resources, AI policy and variants. A deterministic variant is assigned and frozen when a student starts; it never changes the rubric or assessed objectives. All students still submit individual evidence, including when a group artifact is allowed. Group roster/collaborative authoring is not implemented.

Existing `nova_release_course` atomically stores the professor-private course version alongside sanitized publication. New demonstrations record that publication version. Submission synthesis retrieves the private evaluation guide from that immutable release, never from the professor's current draft. It remains server-only and is not attached to the student-readable demonstration. Existing attempts without the new metadata work as before.

Students submit the artifact and explanation, answer two adaptive follow-ups, complete a changed-scenario task, and disclose assistance (including “none”). Extended verification also requires reflection. Typed and existing transcribed-voice responses work. This edit does not add binary image/video uploads or vision grading. Existing Evidence Review remains the final human decision point; no grades, cheating scores or mastery estimates are generated by this design engine.

## Export and limitations

- Student JSON export contains the public assessment only; private design JSON contains hidden evaluation guidance and is labeled professor-private.
- Preview is an explicitly scripted template workflow stored in the current browser tab. It exercises state transitions, not actual pedagogical generation. Replace template case details before classroom use.
- Duration checks validate specified minutes, not real student completion time. Variant equivalence and accessibility require professor/pilot review; they are not psychometrically validated.
- AI policy is visible and requires disclosure; it is not browser surveillance or reliable AI-use detection.
- Subject accuracy, model quality, live Supabase policies and real microphone behavior require credentialed acceptance testing. No new external service was connected in this edit.
- No LMS sync, autograding, scheduled assessment release, new mastery model, or evidence-engine rewrite is included.
